# Socket 消息通道恢复实施计划

> 设计依据：`docs/superpowers/specs/2026-08-19-socket-message-channel-recovery-design.md`

## 目标

浏览器 Worker 正常运行时只依赖 WebSocket 接收消息；不再周期性执行 `chat.listAll` 或扫描历史私聊。Socket 断开后先重连，再对启用群聊与仍需私聊输入的活跃流程执行一次补偿扫描。网络超时不得误判为登录失效，也不得让一个群的异常堵塞其他群。

## 成功标准

- Socket 健康时没有周期性房间发现或历史扫描。
- 断线重连成功后，每个补偿目标只扫描一次，并用既有去重机制避免重复入站。
- 私聊目标只包含随机事件投稿草稿、数字炸弹报数玩家、德州活跃玩家；普通私聊不进入核心处理。
- 只有明确的 401/403、身份缺失或登录页状态进入人工登录；超时、断网、Socket ACK 超时仅触发重连。
- 多群并行时，一个房间的读取或发送失败不影响其他房间。
- 聚焦测试和全量测试通过；本计划完成后停在部署前等待确认。
