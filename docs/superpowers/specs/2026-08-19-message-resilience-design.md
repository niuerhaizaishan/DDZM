# 消息通道韧性与人工验证设计

## 目标

在平台 HTTP 接口返回 `418 captcha_required` 时，保持群聊实时 Socket、游戏指令和出站发送继续工作；通过独立影子同步通道及时补齐 Socket 漏掉的消息，并允许管理员在不停止主 Worker 的情况下完成服务器 IP 真人验证。同时修复空心跳清除机器人名称、导致艾特无法触发 AI 的问题。

## 已确认的行为

- Socket 是实时消息主通道。
- 影子同步通道默认约每 60 秒请求一次，并加入随机抖动。
- 影子通道取得的新消息立即进入现有幂等入站流程，不等待 Socket 明确断开。
- 遇到 418 时保留游标和补拉任务，按 2、5、10 分钟退避；后续保持 10 分钟间隔，成功后恢复正常周期。
- 人工验证使用独立可视浏览器桌面，不停止主 Browser Worker，也不关闭主 Socket。
- 空名称心跳不得覆盖最后一次有效机器人名称。
- 部署时恢复当前 Worker 的有效机器人名称，但不主动回放历史艾特消息。

## 架构

### 实时 Socket 主通道

现有 Socket 继续负责 `message:new` 实时事件、房间加入和发送。Socket 回调只把消息放入现有入站执行器，不承担 HTTP 补拉，也不等待影子同步。

Socket 的连接状态与每个群的房间加入状态继续独立记录。影子同步的成功不得把 Socket 状态标记为正常，Socket 正常也不得隐藏影子同步的失败。

### 影子同步通道

Browser Worker 新增一个单任务、独立执行的影子同步器。它使用从当前浏览器会话复制出的 Cookie 和 access token 创建独立 HTTP 会话，不从后台线程操作 Playwright 页面。

同步器批量调用当前前端使用的 `chatroom.syncChatroomMessages`，为每个启用监听的群维护独立游标：

- 最后成功同步时间；
- 最后消息时间；
- 必要时的最后消息 ID；
- 下次允许请求时间；
- 连续失败次数和最近错误。

正常状态下约每 60 秒同步一次，并加入小幅随机抖动，避免固定频率请求。一次只允许一个在途请求，并设置严格超时，因此它不会占用 Socket、出站发送或游戏任务线程。

同步成功后，消息按时间排序并立即进入现有入站流程。Core 继续以来源、群聊和平台消息 ID 唯一约束去重，使 Socket 与影子通道同时收到同一消息时不会重复执行指令、扣款、结算或创建 AI 请求。

### 418 与其他错误

收到 `418 captcha_required` 时：

- 不清除登录状态；
- 不关闭 Socket；
- 不推进或删除同步游标；
- 将影子通道标记为“需要验证”；
- 按 2、5、10 分钟退避，之后每 10 分钟重试。

401 或 403 仍视为真正的认证失效，进入现有人工登录流程。网络超时和 5xx 保留游标并采用普通短退避，但不显示“需要验证”。

Socket 明确断开时，影子同步器获得一次立即同步机会。若立即同步仍返回 418，任务保留并继续退避。Socket 重连后影子同步器仍保持运行，用于覆盖表面连接正常但漏事件、或单个群房间订阅失效的情况。

## 后台人工验证

运行概览新增“平台访问验证”卡片，显示：

- 当前验证状态；
- 影子同步最后尝试和最后成功时间；
- 最近错误和下次重试时间；
- “开始人工验证”“完成验证”“终止验证”操作。

“开始人工验证”启动一套独立的可视浏览器桌面，直接打开平台 `/__captcha/`。该桌面使用独立临时浏览器配置、独立显示号、独立 CDP/VNC/noVNC 端口。它与主 Browser Worker 的浏览器配置和 Socket 完全隔离。

人工登录和人工验证共用互斥操作租约：同一时间只允许一名管理员执行其中一种操作，避免远程桌面和服务器资源冲突。任何管理员可终止异常操作，只有租约持有者可完成当前操作。

平台页面说明验证会临时放行服务器出口 IP，因此验证浏览器无需共享主 Worker 的 Cookie。验证期间主 Worker、Socket、出站发送和游戏任务保持运行。

管理员完成拖拽后，系统周期性以同步接口探测是否恢复 200。恢复后自动：

1. 标记验证成功；
2. 触发所有群立即增量同步；
3. 关闭独立验证桌面；
4. 恢复正常 60 秒同步周期。

“完成验证”按钮用于立即探测和关闭桌面，“终止验证”只关闭验证桌面，不改变监听状态。验证超时同样只清理独立桌面与租约。

验证码轨迹、Cookie 和 Token 不写入 Core、数据库、日志或后台响应。

## 心跳与艾特名称

Core 更新 Worker 心跳时，仅当 `account_display_name` 是非空有效字符串才更新数据库字段。Cookie 缓存恢复只能提供用户 ID、暂时没有 `fullName` 时，数据库继续保留最后一次有效名称。

AI 艾特识别继续读取最后一次有效机器人名称。部署完成后恢复当前 Worker 已被清空的名称为线上机器人现用名称；不重新处理已入库但当时未触发的旧艾特消息。

## 状态与数据边界

Core 保存影子同步运行状态和各群游标，使 Worker 重启后能够从最后成功位置继续，而不是依赖进程内存或重新扫描固定数量的最近消息。状态更新只包含游标、时间和错误摘要，不复制消息正文。

后台状态把以下项目分别展示：

- Browser Worker 登录与监听；
- Socket 总连接及每群加入状态；
- 影子同步状态；
- 服务器 IP 验证状态。

这样“Ready”不会再掩盖 Socket 或 HTTP 同步单独失效。

## 安全与资源限制

- 影子同步最多一个在途请求。
- 所有平台 HTTP 请求设置硬超时。
- 418 使用长退避，不进行高频死循环。
- 验证桌面只监听回环地址，通过现有已认证后台代理访问。
- 独立验证配置目录权限为 0700，运行元数据权限为 0600。
- 任何错误均不得停止正常 Socket 或清空未完成游标。

## 测试与验收

自动化测试覆盖：

- 影子同步不占用 Socket 和出站执行器；
- 正常周期、随机抖动和单在途请求；
- 多群独立游标与批量同步；
- Socket 与影子同步重复消息只执行一次；
- Socket 表面连接正常但漏事件时，影子同步在下一周期补入；
- Socket 断开触发立即同步；
- 418 不推进游标，并按 2、5、10 分钟退避；
- 418 恢复 200 后自动补齐并恢复正常周期；
- 401/403 仍进入认证失效流程；
- 人工验证桌面与主 Worker 并存，开始、完成、终止和超时均不关闭主 Socket；
- 管理员租约互斥和权限检查；
- 空名称心跳保留最后有效名称；
- 多群艾特消息补入后能够创建 AI 请求；
- 后台准确展示 Socket、影子同步和验证状态。

上线验收要求：

1. 主 Worker、Core、AI Worker、Memory Worker 和 Admin 均为 active；
2. 主群和其他启用群 Socket 均为 connected；
3. 人工验证开启期间发送普通指令仍能得到回复；
4. 制造一次 Socket 漏消息后，影子同步在一个周期内补入且不重复执行；
5. 空名称心跳后艾特机器人仍能触发 AI；
6. 队列无持续堆积，服务无新增重启。
