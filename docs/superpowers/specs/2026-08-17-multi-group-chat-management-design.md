# 多群聊管理与群级玩法隔离设计

## 目标

把当前由 `DZMM_CHAT_URL` 固定单群运行的系统升级为后台可配置的多群运行模式。单个 Browser Worker 同时监听多个群，员工、经济、部门、档案和 AI 稳定画像全局共享；群消息、临时玩法、随机事件、红包和当前对话上下文按群独立。新增或停用群聊实时生效，不依赖服务重启。

## 已确认的产品规则

### 多群与共享数据

- 后台可新增多个群聊，机器人同时监听并回复。
- 员工、工号、名称、余额、流水、部门、职位、档案、档案形象、物品、商店、打卡、AI 额度、稳定画像与活动事实全局共享。
- 各群游戏独立：A 群的活动玩法不阻止 B 群创建或进行玩法。
- 同一员工可同时参加不同群的游戏；全局余额仍必须防并发透支。
- 所有每日发起、参与和使用次数按员工全局共享；在任一群消耗后其他群同步计入，不能用跨群切换绕过。核心董事会等既有不限次数权益不变。
- 当前群的通用游戏指令只命中当前群，不跨群寻找“该员工正在参与的游戏”。

### 群聊配置字段

每个群聊配置包含：

- `name`：后台展示名称。
- `chat_url`：当前群聊平台的完整 `/chat?c=...` 链接。
- `chatroom_id`：从 URL 的 `c` 参数提取，平台内唯一且不可手工编辑。
- `listening_enabled`：启用监听。
- `games_enabled`：允许小游戏。
- `random_events_enabled`：允许随机事件。
- `announcements_enabled`：接收定时活动/公告。
- 运行态：连接状态、最近连接时间、最近入站时间、最近出站时间和最近错误摘要。

### 兼容现有主群

- 首次迁移从 `DZMM_CHAT_URL` 解析现有群，创建名为“主群聊”的配置。
- 主群四个开关默认开启。
- 数据库群配置在迁移后成为事实来源；环境变量继续作为首次引导和数据库无群配置时的故障兜底。
- 历史群数据全部归到该主群，不改变员工或经济数据。

## 方案选择

采用“单 Browser Worker 动态多房间”方案：

- 继续复用同一登录会话、认证 Cookie、WebSocket 和 Bot Token。
- Worker 从 Core 周期获取启用群列表，并对每个群执行 Socket join、历史补拉、入站分类和发送。
- Core 以群聊配置主键作为所有群级业务的作用域。

不采用每群独立 Worker，避免进程、端口、登录会话和私聊发现重复；不采用每群浏览器页面，避免内存和页面状态随群数线性增长。

## 数据边界

### 继续全局共享的实体

- `users` 与全部员工资料、部门和职位关系。
- `balance_transactions` 及余额字段。
- 商品、物品和库存。
- AI 稳定画像、候选画像、活动事实和职位额度。
- 各玩法按员工统计的每日发起、参与和使用计数。
- 游戏规则、随机事件场景卡、投稿和回复模板。
- 管理员账号与全局配置版本。

### 必须增加群作用域的实体

- 群入站消息与群出站消息。
- 随机事件日程和随机事件实例。
- 记忆考核对战及等待状态。
- 谁是卧底会话、甩锅、数字炸弹、德州扑克。
- 红包、躲猫猫等群内临时状态。
- 群级玩法互斥摘要。
- 定时公告投递记录和每群随机事件触发记录。
- AI 群对话历史检索。

私聊消息继续以一对一 `chatroom_id` 标识，不强制归属某个群。私聊中的底牌、投稿和报数操作仍通过其关联的活动牌局找到对应群；如果同一员工在多个群同时存在需要私聊输入的同类游戏，私聊命令必须检测歧义并返回按群名称稳定排序的本次候选序号。玩家使用 `/报数 群序号 数字`、`/看牌 群序号` 等带候选序号格式明确目标；只有唯一候选时继续兼容原有无群序号格式。

## 数据模型

### 群聊配置

新增 `group_chats`：

- `id` UUID 主键。
- `name`，长度 1–64。
- `chat_url`，保存规范化后的同源群聊链接；仅迁移生成的待引导主群可暂为空。
- `chatroom_id`，唯一；仅迁移生成的待引导主群可暂为空。
- `listening_enabled`、`games_enabled`、`random_events_enabled`、`announcements_enabled`。
- `created_at`、`updated_at`、`deleted_at`。

名称建立唯一约束，用于后台和 AI 内部来源标注；真正路由始终使用不可变的 `id/chatroom_id`。普通新增与编辑绝不允许空 URL 或空群 ID，待引导空值只能由固定迁移记录使用，并由 Core bootstrap 一次性补齐。

### 群聊运行状态

新增 `group_chat_runtime_states`，每群一行：

- `group_chat_id` 主键和外键。
- `connection_state`：`pending`、`connected`、`failed`、`disabled`。
- `last_connected_at`、`last_inbound_at`、`last_outbound_at`。
- `last_error_summary`，只保存无敏感信息的短摘要。
- `worker_id`、`updated_at`。

配置与运行态分表，避免 Worker 心跳更新触发管理配置版本冲突。

### 群级外键

- 为所有群级活动表增加不可空 `group_chat_id`。
- 现有 `random_events.group_key` 改为引用群聊或由群聊 ID 生成稳定键；唯一活动索引改为 `(group_chat_id, active-state predicate)`。
- 现有各游戏的 `active_key` 从全局常量改为群聊 ID 派生值，或直接建立按 `group_chat_id` 的部分唯一索引。
- `red_packets` 等现有“全局仅一个活动项”索引同样改为按群唯一。
- `inbound_messages.chatroom_id` 保留平台原值，并增加可空 `group_chat_id`；群消息不可空，私聊为空。
- `outbound_messages.destination_chatroom_id` 保留实际平台目标，并增加可空 `group_chat_id` 供群级顺序、审计和补发使用；私聊消息为空。

### 软删除

群聊“删除”只写入 `deleted_at` 并关闭四个开关。历史外键继续指向该行；默认列表隐藏软删除项，审计和历史筛选仍可读取名称。不得物理删除存在历史关联的群记录。

## 后台管理

### 列表与编辑

新增“群聊管理”页面：

- 显示名称、截短链接、四个开关、连接状态、最近收发时间和错误摘要。
- 支持新增、编辑、停用和软删除。
- `chatroom_id` 由服务端解析并只读展示。
- 新增后状态先为“待连接”，Worker 成功 join 后变为“已连接”。

### 链接校验

- 必须为 `https`。
- 域名与迁移主群的群聊平台 origin 相同。
- 路径必须是 `/chat`，查询参数 `c` 必须是非空且不超过 255 字符的单值。
- 规范化时移除无关追踪参数和 fragment，仅保存 origin、`/chat` 与编码后的 `c`。
- `chatroom_id` 和规范化 URL 均不可与未删除配置重复。
- 不接受 Cookie、Token、Authorization 或内嵌用户名密码。

### 并发与审计

- 新增、修改、停用和删除使用现有配置版本与 `If-Match`。
- 记录管理员、动作、群聊 ID、修改前后非敏感字段和时间。
- Worker 运行态心跳不增加配置版本。
- 只有后台管理员可操作；群内核心董事会成员无配置权限。

### 安全限制

- 最后一个 `listening_enabled` 群不能停用或删除。
- 群存在报名、进行、打赏、等待结算或其他活动玩法时不能停用或删除，提示管理员先用当前玩法控制强制结束。
- 停用群后 Worker 退出房间且不接受新消息。删除只允许已停用且没有活动玩法的群。

## Worker 动态多群

### 配置同步

Core 提供内部只读端点返回全部启用群的 `group_chat_id`、`chatroom_id` 和规范化 `chat_url`，不返回敏感登录信息。Worker 启动后及固定短周期同步：

1. 对新增或重新启用群执行 `message:join-room`。
2. 为成功加入的群补拉一次历史并开始实时监听。
3. 对停用或软删除群停止维护；若平台支持 leave-room 则退出，否则在本地接收过滤中禁用。
4. 上报每群连接结果和最近收发状态。

### Socket 接收

- Aikda Socket Gateway 将单一 `self.chatroom_id` 改为启用群 ID 集合。
- 接受群集合中的消息并标记 `source_type="group"`、实际 `chatroom_id`。
- 只有已知一对一房间才标记 `source_type="direct"`；未知房间不因“不在群集合”而自动视为私聊。
- 重连后重新 join 全部启用群和已知私聊房间。
- 历史协调队列按群逐个处理，单群失败记录错误后继续其他群。

### 发送

- 所有群出站消息必须设置 `destination_chatroom_id` 与 `group_chat_id`。
- `delivery_key` 使用群 `chatroom_id`，保证同群顺序；不同群由现有并发发送器并行处理。
- Bot Token 长消息调用时使用该消息目标 `chatroom_id`，不再使用启动时固定的主群 ID。
- 没有明确目标群的系统消息不允许发送；定时作业必须显式为每个目标群建立出站消息。

## Core 入站与路由

### 群识别

- 群入站必须带 `chatroom_id`。Core 查找未删除且 `listening_enabled` 的 `group_chats`，写入 `inbound_messages.group_chat_id`。
- 未配置、停用或软删除群返回“未接受”且不执行业务逻辑，不进入 AI、活动统计或画像。
- 私聊继续通过 `direct_chats` 验证，不需要 `group_chat_id`。

### 回复继承来源群

- 对群入站产生的普通回复默认继承来源 `group_chat_id/chatroom_id`。
- 自动任务、阶段通知和定时公告必须由调用者提供群 ID。
- 回复引用只允许引用同一目标群的原消息；跨群回复降级为普通目标群消息，绝不引用另一群原文。

## 玩法隔离

### 通用路由

`active_gameplay_summary`、`current_gameplay_admin_summary`、`force_end_gameplay` 及所有具体游戏仓储入口增加 `group_chat_id` 参数。群命令从当前入站解析群；后台强制结束使用 `group_chat_id + game_type + game_id` 三元身份防误结束。

### 游戏开关

`games_enabled=false` 时拒绝新建：

- 记忆考核对战
- 谁是卧底
- 甩锅游戏
- 蹦蹦数字炸弹
- 德州扑克
- 红包
- 躲猫猫及其他群内小游戏

已经存在的活动游戏继续完成，加入、操作、退出和结算仍允许；关闭只阻止新建，避免卡住资金或玩法状态。

### 随机事件开关

- 每个 `random_events_enabled` 群按全局场景卡、时间表和间隔规则独立生成日程。
- 日程唯一键包含群 ID、日期和计划时间。
- A 群已有游戏只会让 A 群该次随机事件按原规则跳过，不影响 B 群。
- 关闭后不生成新日程；已存在活动事件继续允许操作与结算。
- 投稿草稿、审核和通过场景卡保持全局共享。

### 红包和私聊歧义

- 红包创建、抢取和到期只作用于来源群，同一群最多一个活动红包，不同群可各有一个。
- 私聊命令如果能唯一关联一个活动牌局则直接处理，并继续接受原有指令格式。
- 同一员工在多个群同时存在相同私聊交互类型时，系统按群名称、群 ID 稳定排序并返回本次 `1..N` 候选及名称；玩家使用 `/报数 群序号 数字`、`/看牌 群序号` 等明确格式。序号只用于当前候选集合，不写入游戏状态；系统不会按最近时间或任意顺序猜测。

## 定时活动与公告

### 每群随机事件

随机事件是群级玩法，按开启随机事件的群分别排期、报名、进行和打赏。场景定义、默认奖励和规则配置全局共享；同一员工参加多个群的事件时，每场按事实独立结算。

### 全局结算、多群公告

- 周考勤、每日活跃、收入榜等全局统计和奖励只计算、写入一次。
- 生成统一结算结果后，为每个 `announcements_enabled` 且正在监听的群分别创建公告出站消息。
- 公告投递记录以 `(job_key, group_chat_id)` 唯一，重复定时任务不会重复发送到同一群，也不会重复发奖。
- 玩法更新公告可由后台选择一个、多个或全部公告群发送；不改变业务状态。

## AI 与记忆

### 当前对话

- AI 群聊历史查询使用当前 `group_chat_id`，取该群最近 15 轮 user/assistant 对话。
- 同一员工在 A 群和 B 群的当前话题不会互相进入上下文。
- 私聊投稿、游戏底牌和报数不进入群对话上下文。

### 稳定画像和最新情况

- 稳定画像消息候选可来自员工在所有启用群的普通群聊，仍排除命令、游戏过程和随机事件过程。
- 查询员工“最新情况”可读取其跨群最近 30 条有效发言；每条内部证据标注群名称和时间。
- AI 输出不必机械播报群名称，除非来源差异与回答有关；不得把一群的即时谈话当作另一群当前正在讨论的话题。
- 后台员工消息增加群筛选，默认“全部群聊”。软删除群的历史仍可审计。

## 管理端当前玩法

- 当前玩法页面增加群聊筛选和群聊名称列。
- 可同时展示多个群的活动玩法，不再只返回全局单条。
- 强制结束请求必须携带配置版本、群 ID、玩法类型和玩法 ID。
- 每群只展示公开状态；谁是卧底身份、数字炸弹报数、德州扑克底牌等私密数据继续禁止进入后台响应。

## 迁移

1. 创建 `group_chats` 和 `group_chat_runtime_states`。
2. Alembic 插入一条固定 UUID 的“主群聊待引导”记录；其 `chat_url/chatroom_id` 暂为空、四个开关暂关闭。迁移不读取环境变量。
3. 为现有群消息、出站群消息、随机事件、游戏、红包、躲猫猫和日程增加可空群外键。
4. 将所有历史群级行回填到固定的主群记录。
5. 将群业务必需外键改为不可空；私聊消息保持为空。
6. 把全局活动唯一索引替换为按群部分唯一索引。
7. Core 启动时执行幂等 bootstrap：发现“待引导”主群后，从 `DZMM_CHAT_URL` 校验并写入规范化 URL 与 `chatroom_id`，开启四个开关并创建运行态。bootstrap 成功后，数据库成为唯一配置来源。
8. bootstrap 未成功时 Core 健康状态明确报告群聊配置未就绪，Worker 不处理群业务；不使用两套并行事实来源静默运行。

迁移必须支持 SQLite 测试和 PostgreSQL 正式环境。升级过程中不复制用户、余额或流水，也不重新触发历史定时奖励。

## 失败与恢复

- 新群 join 失败：运行态标为 `failed`，保存无敏感错误摘要，其他群继续运行；后续同步周期重试。
- Core 暂时不可用：Worker 保留最后一次成功的启用群快照，继续 Socket 连接但暂停无法持久化的业务处理；恢复后补拉历史。
- Worker 重启：从 Core 重新获取群配置、逐群 join 和补拉历史。
- 单群历史补拉失败：记录该群失败，不清空其他群游标。
- 群停用与入站并发：Core 以事务内读取的最新配置为准；停用提交后的新消息不执行。
- 群停用与活动创建并发：锁定群配置并再次检查活动状态，保证停用和新建至多一个成功。

## 测试与验收

### 配置与后台

- 新增、编辑、停用、软删除和列表筛选。
- URL 同源、路径、`c` 参数、重复 ID、敏感内嵌信息校验。
- `If-Match` 并发保护和审计事件。
- 最后启用群保护、活动玩法保护和软删除历史保留。

### Worker 与 Socket

- 启动加入多群、新增群实时加入、停用群退出或过滤。
- 多群实时消息分类、逐群历史补拉、重连恢复和单群失败隔离。
- 未知房间不误判为私聊。
- 同群发送顺序、跨群并发和 Bot Token 长消息目标正确。

### 群级玩法

- 所有通用指令只命中来源群。
- A/B 群可同时运行相同或不同游戏。
- 游戏、随机事件、红包、躲猫猫和等待状态不串群。
- 同员工跨群参与时状态独立、余额共享且并发不透支。
- 私聊同类玩法歧义时要求明确群，不猜测。

### 开关与定时任务

- 监听、小游戏、随机事件、公告四个开关分别生效。
- 关闭小游戏或随机事件不打断已有场次。
- 每群随机事件独立排期和跳过。
- 全局奖励只结算一次，公告按群幂等多发。

### AI 与安全

- 当前 15 轮对话只来自来源群。
- 稳定画像和最近 30 条可跨群，并保留内部群来源。
- 未配置/停用群不进入 AI 或画像。
- 私聊内容、游戏秘密、Cookie、Token 和完整错误堆栈不进入群配置 API、后台或日志。

### 迁移与回归

- 现有单群数据全部关联主群，余额和流水数量、金额不变。
