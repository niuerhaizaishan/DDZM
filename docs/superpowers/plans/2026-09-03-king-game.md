# 国王游戏 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 DZMM 多群玩法系统中交付可重启恢复、可后台配置的国王游戏。

**Architecture:** 使用独立设置、对局和轮次记录保存状态；仓储层原子生成每轮国王与编号映射，命令层只路由和渲染，不读取或保存国王的普通命令文本。现有 gameplay gate、群聊玩法开关、定时任务和管理端配置继续复用。

**Tech Stack:** Python 3.13、SQLAlchemy 2、Alembic、FastAPI/Pydantic、原生 JavaScript/HTML、pytest。

**Spec:** `docs/superpowers/specs/2026-09-03-king-game-design.md`

## Global Constraints

- 玩法标识固定为 `king_game`，显示名固定为“国王游戏”。
- 最少 3 人；报名超时 10 分钟；国王阶段默认 500 秒且后台可配；公开后无超时。
- `/开始` 仅发起人、`/公开` 仅当前国王；`/继续` 与 `/结束游戏` 允许任一参与者。
- 普通国王命令不做语义校验、不保存、不进入记忆或画像；没有摸鱼币变动。
- 每轮重新抽取国王并随机编号；公开时显示完整映射，国王可点自己。
- 当前工作区存在其他未提交改动；只暂存本玩法涉及的文件。
