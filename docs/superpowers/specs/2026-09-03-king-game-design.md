# 国王游戏设计

## 范围

在已有多群多人玩法框架中新增 `king_game`。它不产生摸鱼币、不会解释或保存国王发布的命令内容，只负责轮次、国王、隐藏编号与公开结果。

## 群内流程

1. 任一已入职员工发送 `/国王游戏` 创建报名局并自动加入；其他员工发送 `/加入` 报名。报名人数至少为 3。
2. 发起人发送 `/开始` 开局；不足 3 人时拒绝。报名阶段沿用多人玩法的 10 分钟超时，到期自动取消。
3. 每轮随机选出一名国王，并为所有仍在场玩家重新随机分配 `1..N` 编号。群内只公开“本轮国王是谁”，不公开编号映射。
4. 国王用普通群消息自行发布命令，机器人不解析、不持久化该消息内容。
5. 国王发送 `/公开 编号...`，接受空格、中文或英文逗号分隔的一个或多个不重复编号。机器人公开本轮全部编号映射，并明确列出被点到的玩家；国王可以点到自己。
6. 公开后任一参与者发送 `/继续` 即开始下一轮并重新洗牌编号。

## 权限与退出

- `/开始` 只允许发起人使用。
- `/公开` 只允许当前国王使用。
- 报名或游戏中，参与者发送 `/退出` 立即从整场移除。报名阶段可暂时低于 3 人；开局后若非国王退出使人数少于 3，仍允许当前国王完成本轮 `/公开`，随后自动结束整局并公告。当前国王退出、或轮次已经公开时，则立即结束，避免出现无人可推进的状态。
- 任一参与者可发送 `/结束游戏` 结束整局；核心董事会和后台沿用通用强制结束能力。
- 国王阶段默认 500 秒，可由后台配置。超时不公开编号、不记录命令，直接重新抽取并开始下一轮。
- 公开后的等待 `/继续` 阶段没有额外截止时间。

## 管理与数据

- 后台提供玩法启用开关与国王阶段秒数配置。
- 群聊玩法开关支持单独启用 `king_game`。
- 当前游戏状态展示报名中、国王下令中、已公开等待继续，以及可操作指令；后台可强制结束。
- 帮助与知识卡说明准确指令、权限和流程。
- 不写入长期记忆，不产生经济或玩家画像事实。
