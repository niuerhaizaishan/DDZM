# 暗网交易所玩法设计

## 目标

新增一个全公司共享的匿名虚拟商品竞价市场“暗网交易所”。员工通过私聊自由描述并上架虚拟商品，其他员工私聊竞价，系统使用真实摸鱼币完成冻结、退款、成交与手续费结算。市场不生成可持有的系统物品，不占用群级游戏槽位，并在多群环境中只通过后台指定的暗网群公开市场信息。

## 核心原则

- 商品是玩家自由描述的虚拟商品，不关联“我的物品”库存，也不生成买家藏品。
- 商品、报价人与交易双方在玩家侧默认匿名；后台保留完整身份和审计记录。
- 市场全公司共用，不因群聊拆分；只有后台指定的暗网群可以查询并接收公告。
- 报价使用真实摸鱼币。当前最高报价资金即时冻结，被超过后立即返还。
- 每件商品从正式上架起独立计时，默认满 3 小时结算。
- 玩家端不展示准确截止时间或剩余倒计时；后台可以查看准确截止时间。
- 暗网交易所独立于群级多人游戏互斥，可与其他游戏、随机事件和普通指令并行。

## 玩家流程

### 私聊上架

员工在与总监事的一对一私聊中发送 `/上架暗网`，机器人依次收集：

1. 商品名称，最多 30 字；
2. 用途，最多 100 字；
3. 详细信息，最多 500 字；
4. 匿名性别，只允许“男”“女”或“保密”；
5. 起拍价，只允许 `1–99999` 的整数摸鱼币。

机器人收集完成后展示预览。玩家发送 `/确认` 才正式上架并开始计时。未确认草稿不消耗每日次数，30 分钟无操作自动失效；玩家可以在私聊中发送 `/取消上架` 主动取消草稿。草稿流程不得阻塞该玩家的其他私聊指令或游戏交互。

正式商品生成稳定且不复用的公开编号。正式上架后，无论是否已有报价，普通玩家都不能撤回或编辑。上架引导提示玩家不要在自由文本中填写可识别自己的信息，但系统不使用 AI 审核或改写玩家文本。

### 上架公告与查询

上架成功后，系统在后台指定的暗网群发布一次匿名商品公告，展示：

- 商品编号；
- 商品名称；
- 用途；
- 匿名性别；
- 起拍价；
- 当前状态“竞价中”。

玩家端不展示上架时间、准确截止时间或剩余倒计时。

只有指定暗网群可以使用查询指令：

- `/登陆暗网`：列出全部竞价中商品摘要，包括编号、名称、用途、匿名性别、起拍价、当前最高价和“竞价中”状态；
- `/登陆暗网 编号`：展示指定商品的完整信息。

其他群发送 `/登陆暗网` 时提示“本群不是暗网交易所入口”，不得返回市场内容。私聊不能使用 `/登陆暗网` 查询公开市场。

### 私聊报价

员工在一对一私聊中发送 `/报价 商品编号 金额`。报价规则如下：

- 商品必须仍处于竞价中；
- 金额必须是 `1–99999` 的整数摸鱼币；
- 首次报价不得低于公开起拍价；
- 后续新报价必须至少比当前最高价高 1 摸鱼币，可以一次提高任意整数金额；
- 同一买家可以重复加价，也可以同时参与多个商品；
- 卖家可以给自己的商品报价；
- 玩家必须拥有足够可用余额完成本次冻结。

报价成功后，系统立即冻结新最高报价人的资金。同一最高报价人继续加价时只额外冻结差额。若最高报价被其他人超过，系统在同一事务中返还原最高报价人的全部冻结资金，并私聊通知：“商品 #编号的报价已被超过，冻结的 X 摸鱼币已退回。”通知不得透露新报价人身份。

每次产生新的最高报价后，系统在暗网群匿名公布商品编号和最新最高价，不公开报价人，也不向卖家额外发送私聊。商品详情和 `/登陆暗网` 查询同步显示最新最高价。

### 到期结算

每件正式商品保存独立的准确截止时间，默认是上架成功后的 3 小时。交易时长由后台配置为 1–24 小时，配置变更只影响之后上架的新商品。截止时间不因临近截止的报价而延长。

服务端以接收入站消息的时间判定报价是否早于截止时间。截止前收到且通过事务校验的报价有效；截止后报价一律拒绝。

到期时：

- 没有有效报价：商品流拍，不收手续费，暗网群发布匿名流拍公告；
- 存在有效报价：最高报价人成交，暗网群发布匿名成交金额，随后进入身份公开确认。

成交时将冻结金额转为成交款。系统从卖家应收成交款中扣除手续费，买家只支付自己的最终报价。手续费比例后台可配置，默认 5%；手续费按成交金额计算后向上取整，且只要成交就至少收取 1 摸鱼币。卖家实收为成交金额减手续费。

卖家可以成为自己商品的最终买家。此时仍按正常成交处理：冻结款完成结算，系统照常扣除手续费，因此卖家的实际损失为手续费；不得改按流拍免除手续费。

成交不生成玩家库存、藏品或玩家侧交易历史。后台保存完整商品、报价、冻结、退款、成交、手续费和余额流水记录。

## 匿名身份公开

普通成交后，系统分别私聊买家与卖家，要求在 10 分钟内发送 `/公开` 或 `/不公开`。公开确认只控制身份展示，不影响已经完成的资金结算。

- 双方都发送 `/公开`：暗网群同时公布买家与卖家名称；
- 任一方发送 `/不公开`：立即确定双方继续匿名；
- 任一方在 10 分钟内未回复：按不公开处理，双方继续匿名；
- 卖家自买时只向同一名员工发送一次确认，该员工的一次选择即为最终结果。

一旦确定公开或匿名，后续重复指令不得再次发布身份公告或改变结果。

群内的上架公告、查询结果、报价通知、成交公告和流拍公告不得包含稳定用户 ID、员工编号或真实名称。只有双方按上述规则一致同意后，系统才公开普通成交的双方名称。后台管理员始终可以查看真实身份和完整报价链。

## 职位上架额度

每日成功上架次数按员工当前职位限制，并按北京时间自然日、员工全局共享统计，不能通过切换群聊重复使用。只有正式 `/确认` 上架成功才消耗次数；草稿、取消草稿和校验失败不消耗。

默认额度：

| 职位 | 每日成功上架次数 |
| --- | ---: |
| LV1–LV2 | 1 |
| LV3–LV4 | 2 |
| LV5–LV6 | 3 |
| LV7–LV8 | 4 |
| LV9–LV10 | 5 |
| 核心董事会 | 不限 |

后台按实际职位记录逐项配置每日额度。职位名称以后被管理员修改时，额度继续按稳定职位 ID 关联，不依赖名称匹配。

## 多群与功能边界

暗网市场、商品编号、职位次数和报价记录全公司共享。后台从所有已启用监听的群中选择一个暗网群：

- 新商品上架、最新最高价、成交、流拍、强制下架和身份公开公告只发送到该群；
- `/登陆暗网` 只允许在该群使用；
- 所有员工仍可在已建立的一对一私聊中上架、报价和确认身份公开；
- 存在竞价中商品时，后台不能清空或更换暗网群，也不能关闭该群监听；管理员须等待商品全部结算或逐件强制下架。

暗网交易所不进入 `/当前游戏`，不占用群级多人玩法锁，也不受德州扑克、数字炸弹、谁是卧底、随机事件等玩法状态影响。玩家参与暗网竞价时仍可正常聊天、游戏和使用其他指令。

## 系统设计

### 独立持久化状态机

暗网交易所作为独立子系统实现，不复用单场游戏会话表。建议的数据边界为：

- `dark_market_settings`：总开关、暗网群、交易时长、手续费、配置版本；
- `dark_market_rank_limits`：职位与每日上架额度；
- `dark_market_drafts`：玩家私聊引导步骤、临时字段与草稿过期时间；
- `dark_market_listings`：公开编号、卖家、商品字段、配置快照、状态、起拍价、当前最高价、截止时间和结算结果；
- `dark_market_bids`：商品、报价人、金额、入站消息、时间和结果；
- `dark_market_disclosures`：成交双方的公开选择、截止时间与最终公开状态；
- `dark_market_daily_listings`：员工、北京时间日期和成功上架计数。

商品主状态为：

```text
draft -> active -> sold
                -> unsold
                -> force_delisted
```

`sold` 商品另有独立公开确认状态：

```text
pending -> revealed
        -> anonymous
```

资金结算完成后才进入 `sold`；公开确认失败或超时不能回滚成交。

### 资金与流水

冻结资金通过真实余额扣除和专用余额流水记录，不使用仅存在于内存的预留值。至少记录以下来源：

- 暗网报价冻结；
- 暗网报价退款；
- 暗网成交收入；
- 暗网成交手续费；
- 暗网强制下架退款。

同一报价人在当前最高价基础上自我加价时，只扣除新旧价格差额。被超过时，退款金额等于该报价仍被冻结的完整金额。正常成交后，买家不再发生第二次扣款；卖家收入和手续费从冻结金额中完成守恒结算。

后台余额流水页面增加上述中文来源标签，并能从商品记录跳转或筛选相关流水。

### 并发与幂等

报价事务锁定商品记录，并按稳定用户 ID 顺序锁定涉及的员工余额。事务重新读取当前状态、当前最高价和截止时间后再判断报价是否合法。

多人并发报价时，数据库实际处理顺序决定当前最高价。只有仍高于事务内最新最高价至少 1 摸鱼币的请求成功；落后的请求不扣款。更新当前最高报价、冻结新资金、退还旧资金、写入余额流水、写入报价记录和创建公告发件任务必须在同一事务提交。

同一平台入站消息只能创建一次报价、一次冻结或一次上架。商品结算、强制下架、身份公开决定和所有退款都必须幂等。

### 定时任务与恢复

Core 定时任务处理：

- 已到期且仍为竞价中的商品；
- 已超过 10 分钟且仍等待选择的公开确认；
- 已超过 30 分钟的未确认草稿；
- 因进程重启或暂时错误未完成的结算状态。

结算事务锁定商品，只允许一次状态转换。成交款、手续费、卖家实收、余额流水和商品结束状态在同一事务提交；任一步失败全部回滚，后续任务安全重试。

状态变化与待发送消息在同一事务中写入。消息投递失败只重试消息，不重新执行上架、报价、退款、成交或公开决定。服务重启后继续使用持久化的原截止时间，不重新计时。

## 后台管理

后台新增“暗网交易所”模块，包含：

- 启用或停用新上架；
- 从已启用监听群中选择唯一暗网群；
- 配置交易时长，范围 1–24 小时，默认 3 小时；
- 配置成交手续费，默认 5%；
- 按职位配置每日成功上架次数；
- 查看竞价中、已成交、流拍和强制下架商品；
- 查看准确截止时间、真实卖家、最高报价人、冻结金额、完整报价链、手续费、公开结果和相关余额流水；
- 按精确商品强制下架。

强制下架只允许后台管理员执行，核心董事会没有群内强制下架指令。强制下架时立即返还当前最高报价人的完整冻结资金，不收手续费，关闭公开确认，并在暗网群发布匿名下架公告。重复操作不得重复退款或公告。

停用交易所只阻止创建新草稿和确认新上架，不隐式销毁竞价中商品。既有商品仍允许继续报价并按原配置快照结算，或由管理员逐件强制下架。

## 指令与玩法引导

新增指令：

| 场景 | 指令 | 作用 |
| --- | --- | --- |
| 私聊 | `/上架暗网` | 开始上架引导 |
| 私聊 | `/确认` | 确认当前完整草稿并正式上架 |
| 私聊 | `/取消上架` | 取消未确认草稿 |
| 私聊 | `/报价 商品编号 金额` | 对竞价中商品提交匿名报价 |
| 私聊 | `/公开 [商品编号]` | 同意公开成交双方身份 |
| 私聊 | `/不公开 [商品编号]` | 拒绝公开成交双方身份 |
| 暗网群 | `/登陆暗网` | 查看全部竞价中商品摘要 |
| 暗网群 | `/登陆暗网 商品编号` | 查看指定商品完整信息 |

所有玩家主动指令的成功或失败结果回复定位原消息；自动上架、加价、成交、流拍、强制下架和公开公告独立发送。

新增 `/帮助 暗网交易所` 和对应 AI 权威玩法知识。AI 只解释规则并引导玩家发送准确指令，不能代替玩家上架、报价、确认公开，也不能读取或推测匿名身份。

## 错误处理

- 未入职、额度用尽、字段超长、性别非法、金额非法、余额不足、商品不存在、商品已结束、报价未达到最低要求或报价超过截止时间时，返回明确场景回复，不产生部分写入。
- 暗网群未配置或已不可用时禁止确认新上架，避免创建没有公开入口的商品。
- 玩家已有草稿时再次发送 `/上架暗网`，继续展示当前步骤，不创建第二份草稿。
- 玩家同时存在其他私聊流程时，显式斜杠命令优先按命令路由；普通文本只交给当前暗网上架步骤，不截获其他玩法的明确命令。
- `/公开` 与 `/不公开` 只处理该员工尚未决定且仍在有效期内的公开确认。只有一个候选时可省略商品编号；如同时存在多个待确认成交，机器人列出稳定候选编号，要求使用 `/公开 商品编号` 或 `/不公开 商品编号`，不得猜测目标。

## 验收标准

### 上架与查询

- 覆盖完整引导、预览确认、主动取消、30 分钟过期和并行其他指令。
- 覆盖字段长度、性别、金额、职位额度、北京时间跨日和重复入站消息。
- 覆盖上架后不可撤回、商品编号稳定、仅暗网群可查询和玩家端不显示截止时间。

### 报价与经济

- 覆盖首次报价、最低加价 1、一次提高任意金额、同人差额冻结、多人并发竞价和多个商品并行冻结。
- 覆盖被超过即时退款、余额不足、截止后拒绝、卖家自买和所有余额流水来源。
- 验证任意时刻只有一个当前最高报价，冻结金额与账本一致。

### 结算与公开

- 覆盖流拍不收费、正常成交、手续费向上取整且最低 1、卖家实收和资金守恒。
- 覆盖双方公开、任一拒绝、任一超时、自买单人确认和重复确认幂等。
- 覆盖结算失败回滚、任务重试、服务重启恢复和消息发送失败不重复业务动作。

### 管理与集成

- 覆盖设置版本并发保护、配置快照、暗网群约束、总开关和逐职位额度。
- 覆盖后台查看完整身份与报价链、精确强制下架、冻结退款和重复操作。
- 覆盖暗网与各类游戏和随机事件同时运行、多群共享市场、其他群入口拒绝、帮助与 AI 准确指引。
