# 记忆考核公会赛设计

## 1. 目标与边界

在现有记忆考核旁新增独立的“公会赛”模式。比赛由一名主持人创建，两支队伍参加；每个正式场次由两队各派一名选手进行一对一记忆对战，并通过多场大比分决定冠军。

公会赛只记录比赛胜负，不收取或发放摸鱼币。现有单人记忆考核和双人对战的规则及数据不变。

## 2. 权限与群聊范围

- 所有已入职员工均可创建公会赛并担任主持人，不限制每日发起次数。
- 主持人不能同时成为任一队伍成员。
- 公会赛按群聊隔离：同一群同时只能有一场，不同群可并行举行。
- 公会赛受对应群聊的“记忆考核”玩法开关控制。
- 公会赛从创建到结束占用该群多人玩法锁；同群其他多人游戏和随机事件不能创建或加入。
- 随机事件排期到点时若该群公会赛仍在进行，该次事件按现有规则直接跳过，不打断、也不补触发。
- 主持人可在群内发送 `/结束游戏` 结束比赛；董事会管理员可在群内强制结束；后台也提供强制结束操作。
- 不提供选手 `/投降`，也不设置配置、选人或等待主持操作的自动结束时间。

## 3. 创建与队伍配置

主持人在群内创建：

```text
/记忆考核 公会赛 3
```

末尾数字为预设正式场次数，只允许 `1` 至 `20`。

主持人随后配置队伍：

```text
/队伍1 女仆公馆队
/队伍1人员 G，彻，苏白
/队伍2 摸鱼事务所队
/队伍2人员 玩家A，玩家B，玩家C
```

- 人员列表兼容中文逗号、英文逗号及常见空白。
- 重复发送队名或人员指令时覆盖原配置。
- 仅已入职员工可入队，名称必须唯一且完整匹配。
- 两队名称不能相同；同一玩家不能同时属于两队。
- 第一个场次进入选人后，队名和人员名单永久锁定。
- 进入第一场选人前，两队人数都必须不少于预设正式场次数，确保正常场次每人只出战一次。

## 4. 场次配置与选人

场次逐场配置，不要求开赛前一次设置全部赛制。主持人发送：

```text
/第1场 4/7
```

`4/7` 表示七局四胜。赛制必须满足：总局数为正奇数，获胜数等于严格过半数，例如 `2/3`、`3/5`、`4/7`。场次编号必须连续，上一场结算前不能创建下一场。

当前场次创建后，两队各自由任一队员私聊总监事提交：

```text
/上场 玩家名称
```

- 提交者只能为对应队伍成员，只能选择本队成员。
- 每队首个有效选择立即锁定，不能更换。
- 正式场次不能选择本次公会赛中已经出场过的选手。
- 两队均完成选择后，系统才在发起群同时公布双方选手，避免后提交一方针对选人。
- 如果玩家同时参加多个群的公会赛，私聊中先返回候选群列表，再要求按 `/上场 群序号 玩家名称` 提交。

## 5. 小局对战

双方选手公布后，每个小局都由主持人在群内手动发送：

```text
/开始对战
```

系统行为：

1. 使用现有记忆考核第 `5` 级规则生成一份新题。
2. 使用现有“双人对战展示秒数”展示题目并按现有撤回机制撤回。
3. 撤回完成后进入作答阶段；作答期限复用现有“双人对战作答超时”设置。
4. 仅当前出战的两名选手可在群内发送 `/答案 内容`。
5. 答错后仍可继续作答，不扣摸鱼币、不限制错误次数。
6. 第一个完全答对的选手赢得当前小局；并发正确答案必须在事务中原子判定，只能产生一个胜者。
7. 超时仍无人答对时，本小局记为平局，不增加任何一方胜场。比赛回到等待主持开题状态，主持人再次发送 `/开始对战` 生成新题。

其他队员和观众提交的 `/答案` 不进入判定。上一小局尚未结算时，主持人不能重复开始新题。

## 6. 场次与整场比赛结算

- 某位选手率先达到该场目标胜场后，本场立即结束，对应队伍的大比分加一。
- 每个正式场次只使用一对选手；该对选手完成整个 `2/3`、`3/5` 或 `4/7`，而不是每小局重新换人。
- 所有预设正式场次必须全部打完，即使某队已经提前取得无法被追平的优势也不提前结束。
- 预设场次打完且大比分不同时，系统立即结束比赛并公布冠军。
- 预设场次打完且大比分相同时，比赛进入等待加赛状态。主持人继续用顺延编号创建加赛，例如预设两场后以 `/第3场 4/7` 创建加赛。
- 加赛允许选择已经在正式场次中出场过的选手；加赛仍使用相同的私聊锁定选人和小局规则。
- 加赛场次必然产生一方场胜者；该场结束后直接决定最终冠军。
- 主持人或管理员强制结束时，保留已经结算的所有历史，但比赛状态标记为“强制结束”，不虚构冠军。

## 7. 消息样式

公会赛群消息统一使用简洁的分隔线、队伍色标和少量图标。核心模板示例：

```text
━━━━━━━━━━━━━━
⚔️ 第1场 · 七局四胜
━━━━━━━━━━━━━━
🔴 G
        VS
🔵 彻

🧠 当前小局：第1局
📊 本场比分：0 : 0
🎙️ 请主持人发送 /开始对战
━━━━━━━━━━━━━━
```

最终结算示例：

```text
━━━━━━━━━━━━━━
🏆 公会赛结束
━━━━━━━━━━━━━━
👑 冠军：女仆公馆队
📊 最终大比分：2 : 1

⚔️ 第1场：4 : 2
⚔️ 第2场：3 : 4
⚔️ 第3场：4 : 1

✨ 恭喜女仆公馆队赢得本次公会赛！
━━━━━━━━━━━━━━
```

创建、选人完成、题目撤回后开始作答、小局胜利、平局、场次结束、等待下一场、加赛和强制结束均使用同一视觉语言。

## 8. 数据与后台

使用独立公会赛数据模型，复用现有记忆题目生成器和记忆考核配置，不把队伍字段塞入现有单人/双人记录。

至少保存：

- 比赛群聊、主持人、状态、预设场数、创建/开始/结束时间。
- 两支队伍名称及完整成员快照。
- 每个场次的编号、赛制、双方选手、胜场比分和胜方。
- 每个小局的题目、标准答案、开始/撤回/截止/结算时间、双方作答记录、胜者或平局原因。
- 最终大比分、冠军；或强制结束操作者与原因。

管理端“记忆考核”新增：

- 当前公会赛状态、队伍、对阵和比分。
- 强制结束按钮。
- 公会赛历史分页与详情，完整展示队伍比分、各场对阵、每个小局胜负和平局以及最终冠军。

单人和双人现有配置界面保持不变；公会赛明确显示“固定5级、复用对战展示与超时”。

## 9. 指令、AI与记忆边界

新增或扩展以下指令：

- `/记忆考核 公会赛 场数`
- `/队伍1 队名`、`/队伍2 队名`
- `/队伍1人员 名称列表`、`/队伍2人员 名称列表`
- `/第N场 胜场数/总局数`
- 私聊 `/上场 玩家名称`
- `/开始对战`
- `/答案 内容`
- `/结束游戏`

帮助页和AI玩法知识需要说明完整流程，并只引导玩家发送准确指令。

比赛中的题目、答案、配置指令和中间对话不进入玩家长期记忆。比赛正常结束后，每名参赛者只记录一条稳定事实：参加了本次记忆考核公会赛及所属队伍、最终胜负；主持人记录主持事实。强制结束的比赛只记录参与，不记录胜负。

## 10. 并发、恢复与验证

- 所有创建、选人、正确答案判定、超时和结算使用数据库事务与行锁，保证重复消息和并发提交幂等。
- Worker或核心服务重启后，根据持久化截止时间恢复展示撤回、答题超时和当前比赛阶段。
- 题目展示消息发送失败时不得开启作答窗口；撤回失败沿用现有记忆考核的安全处理。
- 群聊目标、私聊候选与所有出站消息必须保留正确的多群作用域。
- 测试覆盖命令解析、配置覆盖与锁定、人员校验、私聊多群选人、正常场次不可复用、加赛可复用、答错重试、并发首个正确答案、平局超时、全部预设场次、加赛、权限、强制结束、服务恢复、群隔离、后台历史及现有单人/双人回归。
